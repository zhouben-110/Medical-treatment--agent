## 总览

三个里程碑将一个「LangGraph 硬编码工作流」重构为「Supervisor 多 Agent + MCP 解耦知识层 + 量化评估」的现代架构：

| 里程碑 | 主题 | 核心变更 |
|---|---|---|
| M1 | 知识层抽成 MCP Server | 疾病数据迁入 Postgres, 独立 MCP Server, agent 用 MCP Client 消费 |
| M2 | Workflow → Supervisor 多 Agent | Supervisor 路由, 分诊/急诊 Agent, Pydantic 结构化输出 |
| M3 | Eval 工具 + 量化指标 | 35 eval case, 诊断命中率/追问轮数/急症召回率 |

## M1: 知识层抽成 MCP Server（已完成）

### 背景

原系统医学知识检索是**进程内直接函数调用**：`knowledge_base.py` 里 25 种疾病硬编码在 Python list，`vector_store.py` 做 pgvector 检索，`retriever.py` 合并两通道。耦合紧，无法独立部署或复用。

### 关键决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 传输方式 | stdio（Claude Desktop）+ 直接函数调用（App） | App 侧无需 HTTP 中间层，直接调用 `medical_kb_mcp.db` / `vectors`；stdio 给 Claude Desktop 即插即用 demo |
| 工具粒度 | 原子工具 (primitives) | 最能体现 agent 动态选工具 (M2), 且每个工具可单独演示 |
| 仓库关系 | 独立包 + 共享 Postgres | 知识逻辑在 `medical_kb_mcp` 包中，`app/rag/retriever.py` 直接调用，无重复代码 |
| 疾病表 schema | `symptoms text[]` + GIN 索引 + `symptom_embedding vector(1024)` | 数组重叠算子保留兼容，pgvector cosine 语义匹配替代 Dice 评分 |

### 新增文件

```
backend/medical_kb_mcp/           # 独立 MCP Server 包
  server.py                       # FastMCP 应用 + 3 个工具 + stdio/http 启动
  db.py                           # Postgres 疾病表访问 (Dice 匹配)
  vectors.py                      # pgvector + DashScope 嵌入
  models.py                       # Disease ORM 模型
  config.py                       # MCPSettings (读同一 .env)
  seed_diseases.py                # 25 种疾病种子数据
```

### 修改文件

- `app/rag/retriever.py` → 直接调用 `medical_kb_mcp.db` / `vectors` 函数（无 HTTP 中间层）
- `app/main.py` → lifespan 创建 `MedicalRetriever()` 注入节点（无需 MCP tools 加载）
- `alembic/versions/m1diseases001_*.py` → diseases 表迁移
- `requirements.txt` → 新增 `mcp`, `dashscope`

### 后续简化（M1 之后）

App 侧不再经过 MCP HTTP 传输，直接调用 Python 函数：

- 删除 `app/mcp_client.py`（原 MCP Client HTTP 封装）
- `retriever.py` 从 MCP tool 编排器简化为直接函数调用
- MCP Server 保留给 Claude Desktop stdio 模式使用

### MCP 工具契约

| 工具 | 入参 | 返回 |
|---|---|---|
| `search_diseases_by_symptoms` | `symptoms: list[str]`, `limit: int` | `list[DiseaseMatch]`（pgvector cosine 相似度排序） |
| `get_disease_detail` | `name: str` | `DiseaseDetail \| None` |
| `search_guidelines` | `query: str`, `k: int` | `list[GuidelineChunk]` |

### 数据流

```
diagnose 节点 ─┐
advise 节点  ─┤→ app/rag/retriever.py ─┐  (asyncio.gather 并行)
              │    (直接函数调用)        ├─► medical_kb_mcp.db    ─► pgvector(diseases 表, cosine 相似度)
              │                          └─► medical_kb_mcp.vectors ─► pgvector(guidelines 集合)
Claude Desktop ─(stdio)──► medical_kb_mcp.server ─┘
```

## M2: Workflow → Supervisor 多 Agent（已完成）

### 背景

原 `graph.py` 是简单的 4 节点线性流, 硬编码条件边: `analyze → [conditional] → question / diagnose → advise`。没有分诊能力, 急诊场景完全依赖 LLM 判断; 症状提取用脆弱的 `_grab_line` 文本解析。

### 关键变更

#### 1. Supervisor 路由 (`graph.py`)

新增 `supervisor` 节点 (LLM + 确定性兜底), 取代硬编码的 `route_after_analyze`:

```
ENTRY → supervisor → triage → [emergency? END] → supervisor
                      → analyze → supervisor → question → END
                                → diagnose → advise → END
```

- Supervisor 是 LLM 节点, 路由决策在 LangSmith 中完整可见
- `_deterministic_route()` 兜底确保 LLM 返回无效值时不出错
- 每个 Agent 完成后回到 Supervisor, 由 Supervisor 决定下一步

#### 2. 分诊/急诊 Agent (`nodes/triage.py`)

双层检测:
- **Layer 1**: 确定性红旗关键词匹配 (29 个关键词, 零延迟, 不调 LLM)
- **Layer 2**: LLM 结构化输出分诊 (`TriageResult` Pydantic 模型)

命中红旗 → 设置 `is_emergency=True`, 直接短路到 END, 不经过 LLM 推理。

#### 3. Pydantic 结构化输出 (`nodes/symptom_analyzer.py`)

替换 `_grab_line` 脆弱解析:

```python
class SymptomExtraction(BaseModel):
    symptoms: list[str]
    severity: Literal["轻度", "中度", "重度"]
    need_more_info: bool
```

使用 `llm.with_structured_output(SymptomExtraction)`, Pydantic 保证输出格式。

#### 4. 状态扩展 (`state.py`)

新增字段:
```python
is_emergency: bool       # 是否为紧急情况
red_flags: list[str]     # 检测到的红旗症状
emergency_message: str   # 急救提示消息
```

### 新增文件

```
backend/app/nodes/triage.py                    # 分诊/急诊 Agent
backend/tests/test_triage.py                   # 16 个测试
backend/tests/test_symptom_analyzer_structured.py  # 8 个测试
```

### 修改文件

- `app/graph.py` → Supervisor 节点 + triage 节点 + 路由逻辑重写
- `app/nodes/symptom_analyzer.py` → Pydantic 结构化输出
- `app/state.py` → 新增急诊字段
- `app/nodes/__init__.py` → 导出 `run_triage`
- `app/routers/chat.py` → 更新 `PROGRESS_NODES` 和 `_build_graph_input`
- `requirements.txt` → 新增 `langgraph-supervisor>=0.0.31`

### 架构亮点

1. **多 Agent 协作 trace**: Supervisor → Triage → Analyze → Diagnose → Advise 链路在 LangSmith 完整可见
2. **急救不交给 LLM**: 红旗症状确定性检测, 0 延迟短路, 安全叙事强
3. **结构化输出**: 干掉脆弱文本解析, Pydantic 保证输出格式

## M3: Eval 工具 + 量化指标（已完成）

### 背景

「我能测量 agent 质量并迭代」是从「玩具 demo」到「工程师」档次的分水岭。需要量化三个核心指标: 诊断命中率、平均追问轮数、急症召回率。

### Eval 数据集

35 个 eval case, 从 25 种疾病自动生成:

| 类别 | 数量 | 说明 |
|---|---|---|
| 正常 | 25 | 每种疾病 1 个, 用户消息基于真实症状描述 |
| 急诊 | 5 | 胸痛、中风、呼吸困难、呕血、高热抽搐 |
| 模糊 | 5 | 症状不典型或跨疾病, 测试追问能力 |

### 三个核心指标

| 指标 | 计算方式 | 当前值 | 目标 |
|---|---|---|---|
| 诊断命中率 | expected_disease ∈ Top-3 results | 92.0% | ≥60% |
| 平均追问轮数 | start→diagnose 间的 question 节点数 | 0.7 | <3.0 |
| 急症召回率 | emergency case 中被正确检出的比例 | 100.0% | 100% |
| 急症精确度 | 被检出为急诊中真正急诊的比例 | 100.0% | 100% |

### 文件结构


## RAG 优化：Embedding 语义匹配（已完成）

### 背景

M1 的疾病症状匹配使用 PostgreSQL `overlap` + Dice 系数，只做精确字符串匹配。`"头疼"` 和 `"头痛"` 被视为完全不同的症状，无法处理同义词/近义词场景。

### 关键变更

#### 1. Disease model 新增 embedding 列 (`models.py`)

```python
symptom_embedding: Mapped[list[float] | None] = mapped_column(Vector(1024), nullable=True)
```

- 1024 维，对应 DashScope `text-embedding-v3` 输出
- 保留原有 `symptoms TEXT[]` + GIN 索引（不破坏现有数据）

#### 2. Embedding 函数复用 (`vectors.py`)

新增可复用函数，供 seed 和查询共用：

```python
get_embeddings()     # 共享 DashScopeEmbeddings 实例
embed_texts(texts)   # 批量 embedding
embed_query(text)    # 单条 embedding
```

#### 3. Seed 自动生成 embedding (`seed_diseases.py`)

- 新疾病：插入时生成 `symptom_embedding`
- 已有疾病：`symptom_embedding` 为 None 时自动补算
- 新增 `ensure_embedding_column()`：自动执行 `ALTER TABLE ADD COLUMN IF NOT EXISTS`

#### 4. 搜索改为向量相似度 (`db.py`)

```python
# 之前：overlap + Dice
Disease.symptoms.overlap(cleaned)  # 精确匹配
score = 2 * len(inter) / (len(dset) + len(user_set))

# 之后：pgvector cosine 相似度
distance = Disease.symptom_embedding.cosine_distance(query_embedding)
similarity = 1 - distance  # 语义匹配
```

- 阈值过滤：`SIMILARITY_THRESHOLD = 0.3`
- `matched_symptoms` 交集信息保留作为辅助参考

### Embedding 策略

| 阶段 | 操作 |
|---|---|
| 写入 | `"、".join(疾病症状)` → DashScope embedding → `symptom_embedding` 列 |
| 查询 | `"、".join(用户症状)` → DashScope embedding → pgvector cosine 搜索 |

### 迁移

部署后运行一次 seed 即可自动完成迁移（加列 + 补算 embedding）：

```bash
cd backend && python -m medical_kb_mcp.seed_diseases
```

### 性能优化（同期完成）

- **检索并行化**：`retriever.py` 中结构化匹配与向量检索用 `asyncio.gather` 并行
- **Structured Output**：`disease_matcher.py` 改用 `llm.with_structured_output(DiseaseDiagnosis)`，消除手动 JSON 解析
