# 医疗Agent设计文档

## 概述

搭建一个个人健康助手Agent，用户描述症状后，AI通过多轮对话分析症状，最终给出治疗建议。

## 技术栈

- **前端**: Next.js 14 + TypeScript + Tailwind CSS
- **后端**: FastAPI
- **AI框架**: LangChain + LangGraph
- **LLM**: 阿里 DashScope (Qwen-plus)，通过 OpenAI 兼容接口调用
- **嵌入模型**: DashScope text-embedding-v3 (1024维)
- **向量库**: pgvector（PostgreSQL 扩展）
- **数据库**: PostgreSQL 17 + asyncpg
- **数据库迁移**: Alembic（异步模式）
- **对话检查点**: LangGraph AsyncPostgresSaver（PostgreSQL）

## 架构设计

### 整体架构

```
┌─────────────────────────────────────────────────────────┐
│                    前端层 (Next.js)                      │
│         聊天界面 │ 历史记录 │ 症状分类                    │
└─────────────────────────────────────────────────────────┘
                          ↕ SSE / REST API
┌─────────────────────────────────────────────────────────┐
│                    API层 (FastAPI)                       │
│     /chat │ /chat/stream │ /history │ /symptoms          │
└─────────────────────────────────────────────────────────┘
                          ↕
┌─────────────────────────────────────────────────────────┐
│                   核心层 (LangGraph)                     │
│      症状分析 │ 追问决策 │ 疾病匹配 │ 建议输出            │
└─────────────────────────────────────────────────────────┘
                          ↕
┌─────────────────────────────────────────────────────────┐
│                    RAG 检索层                            │
│  结构化知识库 (25种疾病) │ 向量检索 (pgvector + DashScope)│
│  MedicalRetriever: retrieve_for_diagnosis / for_advice   │
└─────────────────────────────────────────────────────────┘
                          ↕
┌─────────────────────────────────────────────────────────┐
│                      数据层                              │
│     PostgreSQL (主库 + 向量 + checkpoint)                │
│     Alembic (迁移管理)                                   │
└─────────────────────────────────────────────────────────┘
```

### 数据库统一架构

所有数据存储在同一个 PostgreSQL 实例中：

| 数据类型 | 存储位置 | 说明 |
|---|---|---|
| 业务数据 | `users`, `sessions`, `messages`, `symptom_*` | 通过 SQLAlchemy ORM + Alembic 管理 |
| 向量数据 | `langchain_pg_collection`, `langchain_pg_embedding` | pgvector 扩展，1024维向量 |
| 对话状态 | `checkpoints`, `checkpoint_blobs` | LangGraph AsyncPostgresSaver |

### LangGraph状态机

**流程（外部多轮循环）:**
```
用户消息 → POST /api/chat/stream
              ↓
         症状分析 (analyze)
              ↓
         信息完整? ──否──→ 追问节点 (question) → 返回追问 → END
              ↓ 是
         疾病匹配 (diagnose)
              ↓
         生成建议 (advise) → 返回建议 → END

下一条用户消息 → 重新从 analyze 开始（外部循环，非图内循环）
最多追问 5 轮 (MAX_USER_TURNS)，超过后强制进入疾病匹配
```

**状态定义:**
```python
class MedicalAgentState(TypedDict):
    messages: List[Message]        # 对话历史
    symptoms: List[str]            # 提取的症状列表
    current_stage: str             # 当前阶段: analyzing / questioning / diagnosing / completed
    confidence: float              # 诊断置信度
    possible_diseases: List[str]   # 可能的疾病
    treatment_plan: str            # 治疗建议
    need_more_info: bool           # 是否需要更多信息
    session_id: str                # 会话ID
    retrieved_context: str         # RAG 检索到的医学知识上下文
```

**核心节点:**
1. **症状分析节点 (analyze)** — 从用户描述中提取症状，识别关键信息
2. **追问决策节点 (question)** — 判断信息是否完整，决定追问内容；图执行到此终止，等待下一轮用户输入
3. **疾病匹配节点 (diagnose)** — 调用 RAG 检索医学知识，结合 LLM 匹配可能的疾病，返回 Top 3 及置信度
4. **建议输出节点 (advise)** — 调用 RAG 检索治疗方案，生成治疗建议，末尾附带免责声明

## API接口设计

### POST /api/chat

发送消息，获取AI回复（同步）。

**请求:**
```json
{
    "message": "我最近总是头痛",
    "session_id": "optional-session-id"
}
```

**响应:**
```json
{
    "reply": "了解了。请问头痛持续多久了？",
    "session_id": "session-abc123",
    "stage": "questioning",
    "symptoms": ["头痛"],
    "need_more_info": true,
    "possible_diseases": []
}
```

### POST /api/chat/stream

发送消息，获取 SSE 流式回复。前端默认使用此接口。

**请求:** 同 POST /api/chat

**响应 (SSE text/event-stream):**
```
event: meta
data: {"session_id":"session-abc123","symptoms":["头痛"],"stage":"questioning","need_more_info":true}

event: chunk
data: {"content":"了解了。"}

event: chunk
data: {"content":"请问头痛持续多久了？"}

event: stage
data: {"stage":"completed"}

event: done
data: {}
```

SSE 事件类型:
- `meta` — 会话元数据（session_id、症状列表、阶段、是否需要更多信息、可能疾病）
- `stage` — 阶段切换通知
- `chunk` — 文本片段
- `done` — 流结束
- `error` — 错误信息

### GET /api/history

获取用户历史对话列表。

**响应:**
```json
[
    {
        "id": "session-123",
        "title": "头痛发烧咨询",
        "created_at": "2026-05-24T10:00:00Z",
        "message_count": 6
    }
]
```

### GET /api/history/{session_id}

获取指定会话的详细记录。

**响应:**
```json
{
    "messages": [
        {
            "role": "user",
            "content": "我最近总是头痛",
            "timestamp": "2026-05-24T10:00:00Z"
        }
    ],
    "diagnosis": "紧张性头痛"
}
```

### DELETE /api/history/{session_id}

删除指定会话，级联清理消息记录和 LangGraph checkpoint。

**响应:**
```json
{
    "detail": "Session deleted"
}
```

### GET /api/symptoms

获取症状分类列表。

**响应:**
```json
{
    "categories": [
        {
            "name": "头部",
            "symptoms": ["头痛", "头晕", "耳鸣"]
        }
    ]
}
```

## 数据模型

业务表通过 Alembic 管理，SQLAlchemy ORM 定义：

```python
# 5 张业务表
users          # id(String PK), created_at
sessions       # id(String PK), user_id(FK), title, created_at, diagnosis
messages       # id(String PK), session_id(FK), role, content, timestamp
symptom_categories  # id(String PK), name(unique)
symptoms       # id(String PK), category_id(FK), name
```

pgvector 自动生成：
```sql
langchain_pg_collection   -- 集合元数据
langchain_pg_embedding     -- 向量数据（1024维）
```

LangGraph checkpoint 自动生成：
```sql
checkpoints       -- 对话状态快照
checkpoint_blobs  -- 状态数据块
```

## 前端界面

### 页面布局

- **左侧边栏**: 新对话按钮 + 历史记录列表（每条显示消息数，悬浮显示删除按钮 ×）
- **右侧主区**: 消息展示区（含阶段标签）+ 输入框（根据阶段动态切换 placeholder）

### 组件结构

| 组件 | 职责 |
|------|------|
| `ChatWindow.tsx` | 主组件，管理状态、调用 SSE 流式接口、协调子组件 |
| `Sidebar.tsx` | 会话列表，支持新建、选择、删除（二次确认） |
| `MessageBubble.tsx` | 消息气泡，根据 stage 显示不同颜色左边框和阶段标签 |
| `SymptomTags.tsx` | 症状标签，绿色药丸样式高亮已识别症状 |

### 关键交互

1. **流式输出** — 默认使用 `/api/chat/stream` SSE 接口，AI回复逐字显示
2. **症状高亮** — 识别出的症状用绿色标签高亮显示
3. **加载状态** — 分析中显示跳动圆点动画
4. **阶段标签** — assistant 消息根据 stage 显示 "追问中" / "已完成" 标签
5. **会话删除** — 侧边栏悬浮 × 按钮，点击后 `window.confirm` 二次确认
6. **动态输入提示** — 根据 `need_more_info` 状态切换输入框 placeholder

## 错误处理

| 场景 | 处理方式 |
|------|----------|
| LLM调用失败 | 降级为预设回复，提示用户稍后重试 |
| 症状无法识别 | 引导用户重新描述，或建议就医 |
| 数据库连接失败 | 内存缓存兜底，异步重试写入 |

**免责声明**: 每次回复末尾附带"仅供参考，不构成医疗建议"

## RAG 医学知识检索增强

### 设计目标

将疾病匹配和治疗建议从纯 LLM 推理升级为基于医学知识库的检索增强生成，提升诊断准确性、减少幻觉、支持溯源。

### 架构设计

```
┌─────────────────────────────────────────────────────────┐
│                    RAG 检索层                            │
│  ┌──────────────────┐  ┌────────────────────────────┐  │
│  │ 结构化知识库       │  │ 向量检索                    │  │
│  │ knowledge_base.py │  │ pgvector + DashScope 嵌入  │  │
│  │ 25种疾病映射表     │  │ data/guidelines/*.md       │  │
│  └────────┬─────────┘  └─────────────┬──────────────┘  │
│           └──────────┬───────────────┘                  │
│                      ↓                                  │
│            MedicalRetriever                             │
│          retrieve_for_diagnosis()                       │
│          retrieve_for_advice()                          │
└─────────────────────────────────────────────────────────┘
                      ↓
┌─────────────────────────────────────────────────────────┐
│                   LangGraph 节点层                       │
│  diagnose: LLM + medical_context → 疾病匹配             │
│  advise:   LLM + medical_context → 治疗建议             │
└─────────────────────────────────────────────────────────┘
```

### 模块设计

#### 1. 结构化知识库 (`app/rag/knowledge_base.py`)

```python
DISEASE_KNOWLEDGE = [
    {
        "disease": "普通感冒",
        "symptoms": ["发热", "咳嗽", "流涕", "鼻塞", "头痛", "乏力"],
        "description": "...",
        "treatment": "...",
        "when_to_see_doctor": "...",
        "severity": "轻"
    },
    # ... 25种疾病
]
```

检索算法：
- `search_by_symptoms(symptoms)`：计算用户症状与每种疾病症状的交集，按 `匹配数/疾病症状总数` 排序，返回 Top 5
- `search_by_disease(disease_name)`：按疾病名精确查找，支持部分匹配

#### 2. 嵌入模型 (`app/rag/embeddings.py`)

使用阿里 DashScope `text-embedding-v3` 模型（1024维），通过 `dashscope.TextEmbedding` 直接调用。

关键约束：单次批量最多 10 条文本，`vector_store.py` 按 `BATCH_SIZE=10` 分批处理。

#### 3. 向量库 (`app/rag/vector_store.py`)

- **存储**：pgvector（PostgreSQL 扩展），集合名 `medical_guidelines`
- **文档加载**：扫描 `data/guidelines/*.md`，`RecursiveCharacterTextSplitter` 按 500 字/50 字重叠分 chunk
- **初始化策略**：检查集合是否已有数据，有则加载；否则从文档创建
- **批量处理**：DashScope API 限制 batch_size <= 10，分批写入
- **连接**：使用 psycopg2 同步连接（PGVector 要求），连接字符串从 asyncpg 格式转换

#### 4. 统一检索接口 (`app/rag/retriever.py`)

```python
class MedicalRetriever:
    async def retrieve_for_diagnosis(symptoms: list[str]) -> str
    # 输出格式：
    # 【知识库匹配结果】
    # 1. 普通感冒（匹配度43%，严重程度：轻）
    #    匹配症状：头痛、发热、咳嗽
    #    描述：由病毒引起的上呼吸道感染...
    # 【医学文献参考】
    # 1. 普通感冒诊疗指南...（向量检索 Top 3）

    async def retrieve_for_advice(diseases: list[str], symptoms: list[str]) -> str
    # 输出格式：
    # 【普通感冒】
    # 描述：...
    # 治疗建议：...
    # 就医指征：...
    # 【普通感冒相关文献】
    # 1. 治疗原则：对症治疗为主...
```

#### 5. 节点改造

**diagnose 节点** (`nodes/disease_matcher.py`)：
- 新增 `retriever` 模块级变量（由 main.py lifespan 注入）
- `match_diseases()` 中先调用 `retriever.retrieve_for_diagnosis(symptoms)`
- Prompt 新增 `医学知识参考: {medical_context}` 段落
- 返回值新增 `retrieved_context` 字段

**advise 节点** (`nodes/advisor.py`)：
- 同样注入 retriever
- `generate_advice()` 中调用 `retriever.retrieve_for_advice(diseases, symptoms)`
- Prompt 新增 `医学知识参考: {medical_context}` 段落

#### 6. State 扩展

```python
class MedicalAgentState(TypedDict):
    # ... 原有字段
    retrieved_context: str   # RAG 检索到的医学知识上下文
```

#### 7. 启动初始化 (`main.py`)

```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    # 数据库初始化
    await init_db()

    # RAG 初始化（异常不阻塞启动）
    try:
        vector_store = await init_vector_store(settings)
        retriever = MedicalRetriever(vector_store.as_retriever(search_kwargs={"k": 3}))
        disease_matcher.retriever = retriever
        advisor.retriever = retriever
    except Exception as e:
        print(f"Warning: RAG initialization failed: {e}")

    # LangGraph checkpoint（PostgreSQL）
    async with AsyncExitStack() as stack:
        conn_str = settings.database_url.replace("+asyncpg", "")
        saver = await stack.enter_async_context(
            AsyncPostgresSaver.from_conn_string(conn_str)
        )
        await saver.setup()
        graph_module.medical_graph = graph_module.build_graph().compile(checkpointer=saver)
        yield
```

### 容错设计

| 场景 | 处理 |
|------|------|
| 向量库初始化失败 | 打印警告，retriever=None，纯 LLM 模式运行 |
| 嵌入 API 调用失败 | 向量检索 try/except 静默跳过，结构化匹配仍可用 |
| 文档目录不存在 | `_load_guidelines()` 返回空列表，创建空集合 |
| 集合已有数据 | 跳过重新加载，直接使用已有索引 |
| DashScope 批量限制 | `BATCH_SIZE=10` 分批添加 |
